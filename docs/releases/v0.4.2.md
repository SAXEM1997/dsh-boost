**中文**

质量仪（issue #20）。到 0.4.1 为止，每一项干预都只记 token 账，没有任何一处回答「结果变差了吗」；两个新分母把收益天花板压到 1.47% / 0.24%，越是这样越该先测「有没有变差」。

- `scripts/quality-tasks.mjs`：从会话日志里挑出以验证命令收尾的任务，产出可重放的任务表。
- `scripts/quality-compare.mjs`：两臂配对比较，输出一致率、token 差、不一致清单；`--min-pairs` 是硬门，样本不足报 `insufficient-pairs`。
- 规程写在 `docs/quality.md`：判据必须预先定死，否则看完数再定标准等于没有标准。
- 边界说清楚：仓库驱动不了 agent 的 A/B。这一版交的是装置的一半——挑任务的机器与比较的算术；跑两遍要在宿主上做。

**English**

The quality instrument (issue #20). Up to 0.4.1 every intervention kept only a token ledger, and nothing anywhere answered "did the result get worse?". The two new denominators push the benefit ceiling down to 1.47% / 0.24%, which makes measuring regressions more urgent, not less.

- `scripts/quality-tasks.mjs`: picks tasks that end in a verification command out of session logs, with the task statement attached (first user message, 400 chars), producing a replayable task table.
- `scripts/quality-compare.mjs`: paired comparison of two arms — agreement rate, token delta, mismatch list; `--min-pairs` is a hard gate and too few pairs reports `insufficient-pairs`.
- The procedure lives in `docs/quality.md`: the pass criterion must be fixed before the run, or deciding after seeing the numbers is no criterion at all.
- The boundary is stated plainly: this repository cannot drive an agent A/B. This release ships half the instrument — the task picker and the comparison arithmetic. Running both arms happens on the host.
