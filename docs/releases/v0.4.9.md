0.4.8 的发布链跑到了最后一步才红：publish、建 release、挂两个 asset 都成功了，最后那条字节断言因为缺 `GH_TOKEN` 报 `exit code 4`。这一版修那个缺漏，并把「重跑」的判据从拒绝改成可验证。

**中文**

- 最后一条字节断言补上 `GH_TOKEN`。`gh` 在没有 token 时拒绝运行，而这个 step 当时是唯一一个调用 `gh` 却没声明 token 的——前面四步都带了。
- 把「已发布且有 release 就拒绝」换成按 `gitHead` 判定。原来那条规则对危险的判断是对的（tag 被移动会让 tag 的树与已发布字节不一致，而 release 页看起来完全正常），但处置是错的：它同时挡住了「发布成功、后面某步失败」这种最需要重跑的情形。npm 记录了 `gitHead`，所以「这个版本是不是用这个 tag 指的 commit 构建的」有答案，不依赖相信 tag——不一致即硬错，一致则跳过发布、刷新 body、重挂 asset、重跑断言。
- 两条回归测试：每条调用 `gh` 的 step 必须带 `GH_TOKEN`；状态步必须比 `gitHead`。
- 0.4.8 那次运行的最后一步是人工复算通过的：latest 是 `v0.4.8`，两个 asset 各 518,662 字节，`releases/latest/download/dsh-boost.tgz` 的 sha1 与 registry 的 `dist.shasum` 相同（`6d82767a…`），`gitHead` 是 `2e6356b…`——即 tag 指向的 commit。

**English**

0.4.8's release run went red at the last step: the publish, the release and both assets had all succeeded, and the final byte assertion failed with `exit code 4` because `GH_TOKEN` was missing. This release fixes that omission and turns the re-run criterion from a refusal into something verifiable.

- The final byte assertion now carries `GH_TOKEN`. `gh` refuses to run without one, and that step was the only one calling `gh` without declaring it — the four steps before it all had it.
- "Published and released → refuse" is replaced by a `gitHead` comparison. The old rule was right about the hazard (a moved tag leaves the tagged tree and the published bytes disagreeing while the release page looks fine) and wrong about the remedy: it also blocked the case that most needs a re-run — publish succeeded, a later step failed. npm records `gitHead`, so "was this version built from the commit this tag names?" has an answer that does not depend on trusting the tag: a mismatch is a hard error, a match skips the publish, refreshes the body, re-uploads the assets and re-runs the assertions.
- Two regression tests: every step that calls `gh` must carry `GH_TOKEN`; the state step must compare `gitHead`.
- 0.4.8's final step was verified by hand: latest is `v0.4.8`, both assets are 518,662 bytes, `releases/latest/download/dsh-boost.tgz` hashes to the registry's `dist.shasum` (`6d82767a…`), and `gitHead` is `2e6356b…` — the commit the tag names.
