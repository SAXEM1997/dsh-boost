**中文**

0.4.5 的准入接线是错的：它在挂载时取一次 `connection`，之后再没重新解析。两个方向都会静默失效。

- 晚激活 = 永久无准入。`connection` 由兄弟 fiber 提供且自身要 `await BrowserAuth.create(...)` 才注册服务；`webServer` 先就绪时那次 `ctx.get` 拿到 `undefined`，这条路由整个进程都不再有准入，且没有任何告警。
- 重载 = 永久 401。连接插件 reload/dispose 后手里是旧 service，`admit` 因 `disposed` 恒返 401，页面一直坏到 boost 自己重载。
- 改为每请求解析一次。顺带收紧三条 fail-open：`ctx.get` 抛错 → 401（此前放行）；畸形 verdict（字符串、缺字段、Promise）→ 401；宿主返回 401/403 之外的数字 → 500 `ERR_HTTP_INTERNAL`，不再冒充认证失败。
- 测试补到能证伪：403 保住 `ERR_HTTP_FORBIDDEN`、未知数字走 500、非受信 `Host` + 401（证明准入先于栅栏）、拒绝写的请求改用合法信封（此前用畸形体，那条「文档没动」的断言恒真）。
- 文档：`curl` 排障改成带 cookie 的两条命令（裸 `curl` 在开启鉴权的宿主上 401 是预期）；`docs-codes` 测试改为扫描 `export const ERR_HTTP_*`。

**English**

0.4.5's admission wiring was wrong: it read `connection` once at mount and never resolved it again. Both directions fail silently.

- Late activation means no admission at all. `connection` is provided by a sibling fiber that must itself `await BrowserAuth.create(...)` before registering the service; if `webServer` is ready first, that `ctx.get` returns `undefined` and the route has no admission for the life of the process, with no warning.
- Reload means a permanent 401. After the connection plugin reloads or disposes, the captured service is stale and `admit` returns 401 forever because it is `disposed`; the page stays broken until boost reloads too.
- Now resolved per request. Three fail-open edges tightened: a throwing `ctx.get` answers 401 (it used to pass); a malformed verdict (string, missing field, Promise) answers 401; a numeric verdict other than 401/403 answers 500 `ERR_HTTP_INTERNAL` instead of impersonating an auth failure.
- Tests now falsifiable: 403 keeps `ERR_HTTP_FORBIDDEN`, an unknown number answers 500, an untrusted `Host` with a 401 verdict proves admission runs before the fence, and the rejected-write case uses a valid envelope (it used a malformed one, so "the document did not move" was vacuously true).
- Docs: `curl` troubleshooting now uses a cookie-carrying pair of commands (a bare `curl` getting 401 on an authenticating host is expected); the `docs-codes` test scans `export const ERR_HTTP_*`.
